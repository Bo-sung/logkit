# 분석 서버 프로비저닝

새 게임 프로젝트의 분석 서버를 등록하고 배포합니다. 수신 서버(`C:\UnityCI\LogServer`)와 같은 주소에서 포트만 나눕니다.

## 사용법

```powershell
# 계획만 출력(아무것도 만들지 않음)
.\new-project.ps1 -Name <프로젝트이름>

# 실제 생성·등록·배포·검증
.\new-project.ps1 -Name <프로젝트이름> -Apply
```

- 이름: 소문자·숫자·`_`·`-`, 32자 이내. 수신 서버 `Projects`의 키와 같아야 합니다.
- 포트: 등록부와 현재 점유 포트를 피해 가장 작은 빈 포트를 씁니다.

## 하는 일

1. 템플릿(`logkit-analytics-template`)을 복제하고 `core` 서브모듈을 로컬 코어 저장소에 연결합니다. `.gitmodules`는 바꾸지 않습니다.
2. 분석 페이지 키와 업로드 키를 새로 만듭니다.
3. 게임 빌드용 프로젝트 업로드 키를 수신 서버 `Projects`에 등록하고 수신 서버를 재시작합니다. 설정 백업을 먼저 만듭니다.
4. 분석 서버를 게시하고, 설정(열람 키, 프로젝트 이름, GM 툴 링크)을 씁니다.
5. 분석 서버를 띄우고 헬스, 미러 동기화, 키 차단을 확인합니다.
6. 방화벽 규칙을 추가합니다(관리자 권한이 없으면 경고만 남깁니다).
7. 키는 비밀 폴더 `C:\UnityCI\secrets\<이름>.txt`에 씁니다. 저장소에는 키를 넣지 않습니다.
8. 등록부 `C:\UnityCI\analytics-registry.json`에 기록하고, 저장소 변경이 있으면 커밋합니다(푸시는 하지 않습니다).

## 등록부

`C:\UnityCI\analytics-registry.json`은 프로젝트마다 이름, 포트, 저장소, 배포 폴더, 비밀 파일 위치를 기록합니다. 새 포트는 여기서 정합니다.

## 주의

- 수신 서버 재시작 동안 업로드가 잠깐 끊깁니다.
- 검증 단계에서 실패하면 수신 서버 설정 백업(`appsettings.<시각>.bak`)으로 되돌립니다.
- 키는 채팅이나 저장소에 옮기지 않습니다. 필요하면 비밀 파일을 직접 엽니다.
